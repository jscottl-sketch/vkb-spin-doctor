## TOP 3 WORST FINDINGS

1. **An automated "MOT stub fix" (commit `c3b366e`) silently overwrote four working functions with empty no-op stubs** — `hitsavStep1`, `hitsavStep2`, `wcLoadActionPlanV2`, `wcLoadMiniTimeline` (mission_control.html:22856-22859). These power the WCCS tab's main "Save Session" / "Copy STATUS.md" 2-step flow and two Work Checker panels. All of them are now dead no-ops — clicking does nothing. This is the textbook FFUEM violation: a patch designed to make a *test* pass broke the *feature* the test was checking for.
2. **Three independent, currently-reachable "save a session" code paths exist and write different artifacts**: (A) the live UI button → `/api/hisav/save-session` → a bare STATUS.md append with no AI, no HISTORY.md, no session log; (B) `aafl_wccs.py` → full AI-rewritten STATUS.md + HISTORY.md + ACCA.md + session_logs + git commit; (C) `wccs_runner.py` (self-labelled "legacy… support only" in its own docstring) → a *third*, differently-formatted session log, still wired to a live server route. `merge_sessions.py` exists purely to reconcile the format drift this causes.
3. **Duplicate element IDs `wccs-chat-input` / `wccs-chat-meta` cause silent data loss** — the user is shown a visible textarea (mission_control.html:2777) and told to paste their session summary there, but `getElementById` always returns the *first* matching element in the DOM — a hidden, empty textarea (line 2469). The user's pasted text is read from the wrong element and is **never saved**, with no error shown.
